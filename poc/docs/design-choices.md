# Design choices

Choices I made where the brief or the architecture left room. Disagree with
any of them by number. "Assumption" means a value I picked, not one I
measured or was given.

## Sandbox and controller

| # | Choice | Why | If you override it |
|---|---|---|---|
| D1 | Drive Docker by shelling out to the `docker` CLI, not the Python SDK. | No dependency; every call is visible as the command it is; the flags map 1:1 to [docker-flags.md](docker-flags.md). | SDK gives typed errors and no subprocess cost. Mechanical swap inside `controller.py`. |
| D2 | One long-lived container per session (`sleep <deadline>` as PID 1) plus `docker exec` per command. | Matches the architecture: the sandbox is created lazily and kept so workspace and scratch survive between calls. Also cheaper per call than a container per command (see cold-start numbers). | One container per command is simpler and gives a clean slate every time, at the cost of one cold start per call and no shared `/tmp`. |
| D3 | A command that times out kills the **whole sandbox** (`docker kill`), not just that command. | Killing only the `docker exec` client leaves the process running inside. Killing the container is the one kill that cannot be dodged. | Cost: background processes and `/tmp` are lost; `/work` survives, and the executor makes a fresh sandbox for the next call. A finer kill would need a supervisor inside the sandbox, which is code agent-supplied code could target. |
| D4 | The sandbox's lifetime is the container's own (PID 1 is `sleep N`), and the executor sets N to the time left in the **session** deadline. | The hard kill is independent of the controller, executor or host staying alive, and no sandbox can outlive its session. | If a sandbox vanishes for another reason the executor replaces it (D30); once the session deadline has passed it does not. |
| D5 | `controller.exec()` lives in the controller. | Architecture says the executor talks straight to the sandbox and the controller only creates and stops. In this PoC `docker exec` needs the Docker socket, which is exactly the privilege the executor must not hold. So the controller carries it. | On Kubernetes the executor would reach a small agent inside the sandbox over the network, and the controller would shrink back to create/stop. This is the biggest deviation from the diagram. |
| D6 | Limits: 1 CPU, 256 MB RAM (no swap), 64 pids, 64 MB `/tmp`, 300 s lifetime, 30 s per command, 1 MiB output cap per stream. | **Assumptions.** Nothing in the brief gives numbers. | All in `Limits` / executor args. |
| D7 | The work dir is a host directory bind-mounted at `/work`, made world-writable (`0o777`) so the unprivileged sandbox user can write to it (needed on both Linux and Docker Desktop, where host chown is unreliable). It must be empty, new, or one a controller created (marked `.agent-sandbox-workdir`, D54); anything else is refused. It may already exist, for a resumed session. A path containing `,` or a newline is refused: it is spliced into a `--mount` option. | Only that one per-sandbox directory is exposed. | Cost: no size limit on it (a sandbox can fill the host disk through `/work`), and any other host user can read it. A named volume with a quota, or an object-store sync (as the architecture says), fixes both. |
| D8 | Image = `python:3.12-slim-bookworm` (pulled from `mirror.gcr.io`) + checksum-pinned static pandoc 3.1.12.3. | Small, reproducible, no apt at build. The mirror is because Docker Hub returned HTTP 429 in my environment; override with `SANDBOX_BASE`. | Both architectures are pinned, but only **amd64 was built and run**; the arm64 pandoc (Apple silicon) is hash-pinned and untested. |
| D9 | The output cap drops the excess rather than failing the command. | A noisy command should not be able to exhaust host memory or hang on a full pipe. `ExecResult.truncated` says it happened. | — |

## Network and proxy

| # | Choice | Why | If you override it |
|---|---|---|---|
| D10 | **Every sandbox gets its own `--internal` Docker network**, and the proxy is attached to it (alias `proxy`). The network is removed when the sandbox stops. | A single shared internal network lets sandboxes of different tenants talk to each other (found in review and reproduced: a tenant-b sandbox read data from a tenant-a sandbox). Turning container-to-container traffic off on the shared network would also cut each sandbox off from the proxy. One network per sandbox gives "reaches only the proxy" for real. | **Cost:** more Docker calls per start (see cold-start.md), and Docker's address-pool size caps how many sandbox networks can exist at once (D36). On Kubernetes this becomes a NetworkPolicy and the limit goes away. |
| D11 | Sandboxes find the proxy by being **configured** (`HTTPS_PROXY`, `SSL_CERT_FILE`, …), not by transparent redirection. | This is the settled design's first mechanism (tool pointed at the proxy) combined with the proxy-signed certificate. Transparent interception (iptables redirect) needs `NET_ADMIN` in the sandbox's network namespace, which I did not want to grant. | Consequence: a tool that ignores the proxy variables gets no route at all, rather than a route with no credential. Both fail closed; the error is just less informative. |
| D12 | The demo and tests call the API with Python `urllib`, not `gh`. | `gh` is not in the image. `urllib` honours `HTTPS_PROXY` and `SSL_CERT_FILE` the way `gh` is expected to, but **`gh` itself was not tried**; the architecture already flags whether `gh` accepts this as unconfirmed. | Adding `gh` to the image and swapping one line in the demo is the next experiment. |
| D13 | The proxy identifies a caller by the connection's source IP, looked up in `registry.json`. Request headers are ignored for identity. | Per the architecture. Tested by sending forged `X-Tenant` headers. | — |
| D14 | The registry holds `agent` as well as session, tenant, epoch. | The proxy needs the agent to find its grants; the brief's list (session, tenant, epoch) wasn't enough. | Could be looked up from the session manager instead. |
| D15 | The registry also keeps the newest epoch ever seen per session. The controller fences in this order: record the new epoch → unregister the old sandbox → kill it. Writers hold a file lock around read-modify-write; readers re-read the file on every lookup (no cache). | A stale sandbox is rejected by the proxy *before* it is dead, so there is no window where both are trusted. A timestamp-keyed cache was removed: on coarse-timestamp filesystems it could keep trusting an unregistered caller. | The epoch table grows forever (never pruned). The lock is a single-host `flock`; several controllers on several hosts would need a real store. |
| D16 | The controller remembers session → sandbox in memory. | Simplest way to find "the old one". | Lost on a controller restart; the registry file survives, but the controller wouldn't know to kill the old sandbox. A real controller would list containers by label. |
| D17 | One `grants.json`: per **agent** (tools, destinations with credential name, placeholder, env var) and per **tenant** (rate limit). One `secrets.json` keyed by tenant then credential name. | The proxy can then only ever fetch a credential from the caller's own tenant's section. | — |
| D18 | The placeholder is swapped in request **headers and query string**, not the body. | Covers `Authorization` and `?token=`; a body swap adds parsing risk for little PoC value. | One more loop in `addon.request`. |
| D19 | Response scrubbing = exact-match replacement of the real value in header values and in the body, applied to the raw header list (so repeated headers survive) and to the body only if it contains the secret (so HEAD / 304 responses are untouched). | Enough to show the mechanism without corrupting responses. | Does not catch an encoded or transformed echo (base64, split across chunks). This is the AUDIT-1 residual risk already in poc-vs-production.md; I did not solve it. |
| D20 | Rate limit: sliding window, per tenant, in the proxy's memory, counted per HTTP request (not per CONNECT). | Simple and testable with a 3-requests-per-5-s tenant. | Per replica only: with N proxies the real limit is N× higher. Needs a shared store at scale. |
| D21 | The proxy verifies its upstream against **only the stub's self-signed certificate**. | Lets TLS to the upstream be real in the PoC. | Production uses the system's public roots, not a single pinned cert. |
| D22 | The proxy's CA private key sits in `.state/proxy-conf/` on the host, one CA for all tenants. | PoC convenience. The key is mounted only into the proxy container. | Production: per-tenant or per-sandbox CA, key in an HSM/KMS, rotation. Already PROXY-1. |
| D23 | **Fail closed, including on bugs.** Unknown caller, stale epoch, unknown agent, agent/tenant mismatch, ungranted host, ungranted port, non-HTTPS, rate limit are denials; and an exception in any hook (missing credential, malformed config) becomes a 500 denial instead of letting the request through. | A first draft logged the exception and forwarded the request with the placeholder (found in review, reproduced). | — |

## Executor and tests

| # | Choice | Why |
|---|---|---|
| D24 | The "model" is a scripted list of `ToolCall(tool, code)`; tools are `bash` and `python`. | Brief says to fake the model. The loop around it is real. |
| D25 | A tool call that isn't granted is returned to the "model" as an error result and the loop continues; hitting the step cap ends the loop. | A real model should see the refusal and adapt. The cap is the runaway backstop. |
| D26 | Tests use real Docker, real mitmproxy and real containers. No mocks. | A mock cannot demonstrate isolation. They need Docker, and take ~40 s. |
| D27 | Tests check that a protection **fails when removed**, not only that things pass. | Two of my first drafts passed vacuously (see docker-flags.md). |
| D28 | Session ids in tests carry a random suffix. | The registry remembers epochs across runs on purpose, so reusing an id would fail on the second run. This was a real test bug I hit and fixed. |
| D29 | Cold start is measured as: `create()` (docker run + network attach + registry write) + the first `exec` of `true`, nearest-rank percentiles, 1 warm-up run discarded. | One definition, stated. |

## Added after review (PR 1)

| # | Choice | Why | If you override it |
|---|---|---|---|
| D30 | The executor replaces a sandbox that has vanished, and re-runs the command, **only when the command never started** (`docker exec` could not find the container, confirmed with `docker inspect`). A command that was running when the sandbox died is reported as failed and **not** retried. | Retrying something that may have half-run could repeat a side effect. | Retrying always is simpler and wrong for non-idempotent commands. |
| D31 | The executor has a **session deadline** (default 600 s, an assumption). It bounds the sandbox lifetime and each command's timeout, and ends the session with an error once passed. | The architecture's deadline is a hard kill for the session, not for one sandbox. Without this a sandbox could expire mid-session and silently return errors. | — |
| D32 | The proxy writes the **audit line before it uses the credential** ("allow"), then an outcome line ("result" with the status, or "error"). If the audit write fails, the request is denied. | No audit record, no credential. A single after-the-fact line missed requests that failed upstream. | Two lines per call instead of one. |
| D33 | Grants may carry `ports` (default `[443]`), and plaintext HTTP is refused. | Grants matched hostnames only, so `http://host` or `host:8443` got the real token. | — |
| D34 | Agent/tenant consistency is checked in three places: executor, controller (only when it has the grants, i.e. with a proxy) and proxy. | The proxy picks the secret by the caller's tenant and the controller picks placeholders by the agent, so a mismatched pair would use another tenant's credential. Cheap to check everywhere; the proxy check is the one that matters. | — |
| D35 | `SandboxController.reap()` removes every labelled sandbox container and network; the test session fails if anything leaks. | The controller's session map is in memory, so after a crash only the labels remember what exists. | — |
| D36 | The number of simultaneous sandbox networks is limited by Docker's default address pools. See the README gaps for the measured number. | A consequence of D10. | Configure a larger pool, or use NetworkPolicy on Kubernetes. |
| D37 | `controller.exec()` takes no stdin; the command's stdin is `/dev/null`. | The only caller never used it, and writing it before arming the timeout could block past the timeout. | If stdin is needed, feed it from a thread so the deadline still covers it. |
| D38 | `stop()` waits until the container is really gone, and every cleanup step runs even if an earlier one fails. | `docker kill` returns when the signal is sent; with `--rm` the container disappears slightly later. Without the wait, "stopped" was not true (a test saw it race under load) and the network could not be removed. | — |
| D39 | One env var standing for two different placeholders is refused at sandbox creation. | The later one would silently win and calls to the other destination would go out with an unswapped placeholder. | — |
| D40 | The proxy's failure handlers use a lookup that cannot raise. | A handler that fails inside the fail-closed wrapper would defeat it: a corrupt registry would have opened the proxy to every host (found in review, reproduced). | — |
| D41 | The query string is rewritten only when it contains the placeholder, and as a list of pairs. | Assigning per key collapsed repeated parameters (`?label=a&label=b`). | — |
| D42 | The executor turns an infrastructure failure (`SandboxError`, `OSError`) into an error result for that step and records the sandbox on the session as soon as it exists. | Otherwise an exception mid-step lost earlier results and leaked the sandbox, its network and its registry entry. A genuine bug (any other exception) still propagates, after cleanup. | — |
| D43 | The controller fences through the **registry**, not only its in-memory map. With a proxy, the epoch check, the epoch bump and a *claim* on the session (a pending registry entry for the new sandbox's name) happen inside one registry transaction, so two controllers racing for one session cannot both win. A stale epoch is refused; an older epoch's sandbox (even one this controller did not start) is stopped; an equal epoch is refused while another sandbox for the session is alive or claimed. If creating the new sandbox then fails, the old one stays stopped and the epoch stays raised (the newer executor owns the session and retries). | Two sandboxes must never hold one session, and a check-then-act across separate lock sections let both through (found in review, reproduced with a race test). | The lock is a single-host `flock`. A claim whose creator crashed blocks an equal epoch for 60 s (`PENDING_TTL_S`, an assumption); a newer epoch supersedes it at once. Registration is conditional on the claim still existing and the epoch not being superseded (`register(..., claimed=True)`), so a controller that loses the race and has already started its container is refused and its sandbox is stopped; and a fence that fails after claiming releases the claim. The existence checks inside the lock are bounded by a timeout (`inspect_timeout_s`, 10 s) so a hung daemon cannot hold it. |
| D44 | `stop()` removes the network only once the container is confirmed gone, runs every cleanup step even if one fails, and re-raises the first failure. `reap()` also unregisters what it kills. | A failing registry write used to skip the kill; a slow daemon used to cut a live sandbox off from the proxy and leak its network. | — |
| D45 | A `.dockerignore` keeps `.state/` (which holds the proxy CA private key) out of the proxy image's build context. | Defence in depth. **Measured:** with BuildKit the context is 506 bytes with or without it, because only `COPY`'d paths are sent, so a review claim that the key was shipped on every build did not reproduce. The legacy builder would send everything. | — |
| D46 | Not fixed, on purpose: the replay edge case in D30 (documented in the README gaps) and Basic-auth placeholders (D18, README gaps). | The first needs a start marker inside the sandbox for no privilege gain; the second is a feature, not a bug, and larger than the PoC. | — |
| D47 | `Sandbox.alive` goes false the moment a stop is requested (no more commands); `Sandbox.stopped` is true only when cleanup fully succeeded. The executor stops anything not `stopped`. | A failed stop must be retryable; gating cleanup on `alive` made one failure permanent. | — |
| D48 | If cleanup fails at the end of a session, the executor appends a "cleanup failed" record and still returns the results. | One bad cleanup should not discard ten good steps. | — |
| D49 | The registry directory is mode 0755 (the controller writes, the proxy reads); the other state directories stay 0777. | The registry decides which caller is which tenant. The others must be writable by uid 65534, which a non-root host cannot arrange another way. | On a shared host, chown them to uid 65534 instead (README gaps). |
| D50 | Both images are pinned to one base by digest, the proxy image installs exact dependency versions from `agent_network_proxy/requirements.txt` (a freeze of the tested image), and `SANDBOX_BASE` is optional. | The same build must produce the same sandbox: the tests were validated against that exact image. The pinned digest was checked against the local image. Versions are pinned, **hashes are not** (a hash-locked file would have to cover every CPU architecture). | Unpin to track security updates, and re-run the tests when you do. |
| D51 | Not reproduced: a review claim that a relative `ca_cert` path breaks `docker run`. It worked here; it is covered by a test as a regression guard and the path is resolved anyway. | — | — |
| D52 | mitmproxy runs with `rawtcp=false`, and a request with an `Upgrade` header is denied. | With the raw-TCP fallback on, bytes that are not HTTP were passed to the upstream server (probed: an SSH-style banner got an immediate EOF from it, with the fallback off the proxy just holds the connection), and none of it was audited, rate limited or scrubbed. WebSocket frames would have bypassed the scrubber the same way. **My first probe misread this**: text that mitmproxy's HTTP parser rejects gets a `400` page in both modes, which I took for relayed data. | Anything that needs WebSockets or raw TCP has no path (PROXY-1). |
| D53 | The controller finds the proxy container by its Compose labels, not by name. | Compose v1, or a different project name, changes the container name. | `ProxyConfig.proxy_container` overrides it. |
| D54 | A work dir is reused only by the session it was created for. The ownership marker is a **file next to the directory** (`<workdir>.sandbox-owner`), not inside it; it must be a regular file (never a symlink, created with `O_NOFOLLOW`) and holds the `tenant/session` owner. A directory with no marker is accepted only if it is empty or new. | The controller makes the directory world-writable and mounts it read-write, so pointing it at a home directory by mistake would expose it, and without an owner one tenant could mount another's directory. A marker inside `/work` could be deleted by the sandbox, stranding its own session (found in review). | The parent directory of the work dir must be controller-controlled. |
| D55 | Grants that are unparsable or wrongly shaped raise `SandboxError`, not `JSONDecodeError`/`KeyError`. | The executor reports infrastructure errors per step and keeps the earlier results. | — |
| D56 | When a command times out, or the sandbox turns out to be gone, a failure while cleaning up is swallowed in `exec()`; the sandbox stays `stopped=False`, so the executor retries the cleanup and reports a failure. | The caller must still learn the command timed out, and a command that never started must still be retried. | A cleanup failure is therefore reported later, not at the moment it happens. |
| D57 | All validation (workdir, mount paths, grants) happens **before** the epoch is fenced. | A `create()` that was going to be rejected used to stop the session's live sandbox and raise its epoch first. | — |
| D58 | "I cannot tell" is never "it is gone": `docker inspect` failures other than "no such object" raise instead of being read as a stopped container. | With the daemon unreachable, `stop()` would have reported a running sandbox as stopped, and the executor would have skipped its retry. The strict check also showed this Docker spells the message in lowercase (`error: no such object`), which the old check hid. | — |
| D59 | The executor keeps **every** sandbox it created and retries cleanup on each one that is not `stopped`. | Only the latest was tracked, so an earlier sandbox whose stop half-failed leaked its network. | — |
| D60 | Sessions are scoped to their tenant: epochs, fencing and the controller's live-sandbox map are keyed by `tenant/session`. | A tenant that reused another tenant's session id could fence and stop that tenant's sandbox. In practice the session manager issues the ids, but the platform's central promise is tenant isolation. | — |
| D61 | An unreadable registry file raises `RegistryError` (an `OSError`), so the executor reports a step error and keeps its results. | A bare `JSONDecodeError` escaped the run. | — |
| D62 | `docker run --pull never`, and the step result carries `truncated`. | A missing local image must be an error, not a pull of that name from a public registry. A silently truncated stdout looked complete to the agent. | — |
| D63 | A failed `create()` that also fails to clean up raises a `SandboxError` naming the sandbox and network it left behind, with the original error chained, and points at `reap()`. | The cleanup error used to be swallowed, so a leaked container and network were invisible. | — |
| D64 | A same-epoch `create()` is allowed again when the previous sandbox for that session has expired on its own (probed with `docker inspect`). | A sandbox that hit its deadline stayed in the controller's map and locked the session out until the epoch was raised. | — |
| D65 | HTTP Basic credentials are decoded, swapped and re-encoded; a placeholder in the URL path or a request body is refused. | git over HTTPS sends `Basic base64(user:token)`, which a literal replace never matched, so the call went out with a fake token and the audit still said "allow". A body or path swap adds parsing risk, so those fail loudly instead. | Other encodings (cookies, form bodies) are not handled. |
| D66 | An empty sandbox address (the container exited at once) is an error. | `register("")` stored a bogus entry and reported success. Not covered by a test: it needs a container that dies between `run` and `inspect`. | — |
| D67 | The proxy scrubs, from every response, the secret itself **and each request header value it rewrote**. | Swapping inside HTTP Basic credentials means an upstream that echoes the header returns the secret only as base64, which an exact search for the secret misses. Making Basic swapping work created that hole; this closes it for echoes of the header. | Any other transformed echo is still not caught (AUDIT-1). |
| D68 | A placeholder in a query parameter *name* is refused like one in the path or body. | It was neither swapped nor refused, so the request left with a fake token while the audit said "allow". | — |
| D69 | `stop()` keeps the sandbox in the controller's map after a failed stop. | It may still be running, and with no proxy the map is the only thing a later fence can see. Cleared only when cleanup fully succeeds. | — |
| D70 | A session-log write failure is recorded on that step's result (`log_error`) instead of raising. | A full disk must not discard the results of a session; the log is the resume record, so the failure is made visible, not hidden. | A caller that needs the log to be durable should treat `log_error` as fatal. |
| D71 | `Caller` refuses a tenant id containing `/`. | `key` is `tenant/session`; without this, (`a/b`, `c`) and (`a`, `b/c`) would share an epoch, a fence and a work dir. | — |
| D72 | `stack.py` gives the audit, stub and proxy-conf directories to uid 65534 with mode 0750 when run as root, and falls back to 0777 otherwise. | Closes them to other users where the host allows it. | On a shared non-root host they remain open (README gaps). |
| D73 | An empty secret or placeholder is an error (the request is denied), and empty needles are never used. | `bytes.replace(b"", x)` inserts `x` between every byte, so one empty entry in `secrets.json` would have corrupted every response. | — |
| D74 | The "allow" audit line is written only after every rewrite of the request has been computed, and the rewrites are applied after it. | The line used to be written first, so a rewrite that failed left an "allow" followed by a "deny" for one request. | Not covered by a test: the proxy addon cannot be imported without mitmproxy, and forcing a rewrite to fail needs a fault injected into the running proxy. |
| D75 | Scrubbing removes the secret, its base64, every rewritten header value, and the bare Basic blob. It does **not** claim to defeat a destination that reflects a credential through further transformations (e.g. base64 of the Basic blob). | A destination that reflects can transform arbitrarily; no finite list of encodings closes that. The control that matters is granting only destinations that do not echo credentials. | AUDIT-1 remains open. |
| D76 | Not changed, on purpose: (a) the `0777` fallback for state directories when `stack.py` is not run as root; (b) `docker inspect` under the registry lock with a fixed claim TTL. | (a) Docker Desktop on a Mac is the stated target and it is single-user; failing there would make the PoC unusable, and it is documented in the README gaps. (b) The inspect is bounded by a timeout, and a snapshot-then-revalidate protocol is a bigger design than this PoC needs. A claim older than 60 s on a loaded host could be treated as abandoned. | (a) Run `stack.py` as root, or chown the directories to uid 65534 yourself. (b) A shared lock service or an owner-liveness lease. |
